Основы агентов

Что такое агент

Агент — AI-система, у которой есть инструкции о том, что делать, ограничения (guardrails) о том, чего не делать, и инструменты для действий от имени пользователя. Система, которая только отвечает на вопросы, сама по себе не считается агентом; агент подключён к другим системам и действует на основании ввода пользователя.

Простые агенты могут использовать несколько инструментов, а сложные агентные системы — координировать работу нескольких агентов. Учебный трек охватывает базовые концепции, инструменты, оркестрацию, примеры применения и практики безопасности.

Модели и построение логики

Базовые составляющие

  • Модели
  • Инструменты
  • Состояние и память
  • Оркестрация

Выбор модели зависит от задачи. Модели с рассуждением могут формировать и проверять гипотезы, что помогает в сложных задачах, но обычно увеличивает задержку и стоимость. Они уместны для планирования, математики, генерации кода и сценариев с несколькими инструментами. Модели без рассуждения быстрее и обычно дешевле — они подходят для простых задач и диалогов, где важна низкая задержка.

В статье рекомендуется начинать эксперименты с универсальной флагманской модели, а затем подбирать модель по сложности, стоимости и задержке. Для диалогового интерфейса предлагается рассмотреть быструю модель для общения и делегировать сложные задачи более мощной. При смене модели следует проверять и адаптировать промпты, а не только заменять название модели.

Responses API и Agents SDK

Responses API даёт гибкую основу и больше контроля над логикой, но разработчику нужно самостоятельно организовать её части. API по умолчанию поддерживает состояние диалога и перенос истории между запросами. Agents SDK — более высокий уровень абстракции для быстрого старта и координации сетей агентов; он упрощает циклы агента, guardrails и трассировку, но может ограничить тонкий контроль. SDK построен поверх Responses API.

Практическое правило статьи: если нужная возможность уже есть как встроенный инструмент, начните с него; к собственным функциям переходите, когда нужна специальная логика.

Инструменты агента

Два способа предоставить возможности

  • Пользовательские инструменты: разработчик описывает функции и ожидаемые параметры; модель может выбрать функцию и вызвать её, но приложение должно выполнить её, передать результат модели и продолжить обработку.
  • Встроенные инструменты OpenAI: обычно выполняются автоматически на инфраструктуре, а результат включается в контекст; исключение в описанном потоке — Computer use, где выполнение действий и передача обновления остаются на стороне приложения.
  • Web search — поиск актуальной информации в интернете.
  • File search — поиск по внутренним материалам; извлекает нужный контекст вместо передачи модели всего массива данных.
  • Code interpreter — выполнение Python-кода, в том числе для анализа файлов и создания результатов вроде графиков или CSV.
  • Computer use — взаимодействие с интерфейсами компьютера; приложение исполняет предложенные действия и передаёт модели обновление, например снимок экрана.
  • Image generation — создание и редактирование изображений.
  • MCP — подключение к размещённым MCP-серверам.

Для поиска по внутренним данным статья описывает RAG: подготовить и при необходимости разбить материалы на фрагменты, создать эмбеддинги и сохранить их, затем найти подходящие фрагменты и передать их модели. Настройка собственной RAG-системы включает несколько этапов; File search предлагает управляемый вариант, который берёт на себя подготовку, эмбеддинги и хранение файлов.

Оркестрация и сотрудничество агентов

Оркестрация — управление ходом диалога: несколькими шагами, использованием инструментов, передачей задач между агентами, guardrails и контекстом. С Responses API это можно организовать самостоятельно; статья рекомендует Agents SDK, если нужны его готовые примитивы для сетей агентов, контекста и ограничений.

  • Agent: модель, инструкции и инструменты.
  • Handoff: передача задачи другому агенту.
  • Guardrail: политика для фильтрации нежелательного ввода.
  • Session: автоматическое сохранение истории диалога между запусками агента.

SDK может автоматически вести цикл агента (вызовы инструментов и функций в нескольких ходах), выполнять handoff с переключением инструкций, моделей и доступных инструментов, запускать фильтры guardrails и вести трассировку. Трассировка помогает выяснить, какие инструменты и агенты использовались и какие ограничения сработали.

Несколько агентов не должны быть вариантом по умолчанию. Их стоит рассматривать, если задачи разделимы и не пересекаются, инструкции очень сложны или для разных задач нужны разные наборы инструментов. Маршрутизирующий агент может определить задачу и передать её специализированному агенту; отдельный агент также может применяться для сложной работы, требующей более сильного рассуждения.

  • Разделение ответственности, например исследование, подготовка текста и проверка качества.
  • Параллельное выполнение задач.
  • Отдельная оценка агентов с учётом их конкретных целей.

Примеры применения и критерии оптимизации

Разные приложения требуют разных компромиссов: скорость важна для частого диалога, надёжность — для сложной задачи с итоговым результатом, стоимость — для частого использования в большом масштабе.

  • Агент поддержки на Responses API с участием человека, который принимает или отклоняет предложения агента.
  • Служба поддержки клиентов, где несколько агентов координируют обработку запроса через Agents SDK.
  • Агент для тестирования интерфейса, использующий компьютер и запускаемый одним вводом пользователя.

Учебный пример

При проектировании учебного помощника можно сначала определить, важнее ли быстрый разговор, надёжное решение сложной задачи или низкая стоимость при большом числе запросов. Это иллюстрация критериев из статьи, а не отдельный сценарий, описанный в ней.

Надёжность и практики безопасности

Агенты могут вести себя непредсказуемо — статья связывает это с природой больших языковых моделей. Подход к надёжности зависит от приложения, пользователей, используемых инструментов, допустимого риска и масштаба.

Если агент принимает пользовательский ввод, можно добавить guardrails, чтобы снизить риск jailbreak и затраты на обработку нерелевантных запросов. Это может быть простое ограничение в инструкциях или многоэтапная система фильтрации.

Если вывод модели будет использоваться приложением, а не только показан пользователю, рекомендуется применять структурированный вывод с фиксированной JSON-схемой. Для пользовательских приложений также можно использовать ограничения выходов, чтобы проверять соответствие правилам. Для производственного запуска следует учитывать оптимизацию стоимости и задержки и мониторинг работы агента.

Итоги

В треке рассматриваются основы агентов, Responses API и Agents SDK, встроенные инструменты, оркестрация и сети агентов, примеры применения и управление пользовательским вводом и выводами модели. Эти темы дают основу для создания агентных приложений; отдельный следующий шаг — изучить подготовку приложений к производственному запуску.
