# Тикеты учебного PDF-агента

Тикеты составлены по `docs/GUIDE.md` и `docs/TASKS.md`. Порядок выполнения сохраняется.
Один тикет — одно учебное занятие; новый тикет не начинаем, пока не пройдены
его проверка и небольшой опыт.

## Правила выполнения

- Работать только с одним тикетом за раз.
- Перед изменениями объяснить ожидаемый результат.
- После изменений выполнить проверку из тикета.
- Завершать тикет можно только при наличии результата, проверки и объяснения.
- После T20 тикеты E01–E06 остаются отложенными.

## Этап A — первый PDF без модели

### T01 — Разобрать круг работы агента

- **Зависит:** нет.
- **Охватывает:** GUIDE §3, §4.
- **Сделать:** прочитать `v0.ts` и `core.ts` без запуска; найти запрос модели, инструменты, выполнение функции,
  результат и следующий запрос; записать объяснение пяти понятий в `LEARNING.md`.
- **Готово, если:** по строке журнала объяснено, что выбрала модель и что сделал бы компьютер; объяснено, почему
  «готово» не доказывает успех.
- **Опыт:** разобрать вымышленный запрос `read_file` без сетевого обращения.

### T02 — Сохранить одну статью

- **Зависит:** T01.
- **Охватывает:** GUIDE §1, §4, §5, §8.
- **Сделать:** выбрать одну короткую статью OpenAI; создать минимальный TypeScript-проект и `npm run source -- "URL"`;
  проверять HTTPS, домен, перенаправления, тайм-аут и размер ответа; сохранять `source.json`.
- **Готово, если:** заголовок и границы текста совпадают с сайтом, меню исключено, чужой домен отклоняется до загрузки.
- **Опыт:** повторно использовать сохранённый текст без новой загрузки.

### T03 — Зафиксировать правила печати

- **Зависит:** нет.
- **Охватывает:** GUIDE §6.
- **Сделать:** сохранить доступный `DESIGN.md` или отметить его недоступность; создать `DESIGN-PDF.md` с источниками и
  нашими правилами A4, шрифта, цветов и блоков; проверить Inter с кириллицей и лицензию.
- **Готово, если:** у каждого используемого значения указан источник или явно отмечено наше дополнение; тестовая фраза
  отображается без пропусков.
- **Опыт:** найти в правилах допустимые цвет и размер одного элемента.

### T04 — Описать документ блоками

- **Зависит:** T02.
- **Охватывает:** GUIDE §5, §8.
- **Сделать:** описать поля документа и постоянные id блоков; поддержать заголовок, абзац, список и учебный пример;
  добавить ссылки на части `source.json` и runtime-проверку полей.
- **Готово, если:** корректный образец принят, неизвестный тип блока и отсутствующая ссылка отклонены с понятной
  причиной.
- **Опыт:** удалить обязательное поле и объяснить место отказа.

### T05 — Показать содержание в HTML

- **Зависит:** T03, T04.
- **Охватывает:** GUIDE §4, §6, §8.
- **Сделать:** создать отображение четырёх типов блоков и отдельные стили; вставлять текст безопасно; разрешить только
  допустимые схемы ссылок; добавить `npm run preview -- "ИМЯ_РАБОТЫ"`.
- **Готово, если:** все блоки видны, `<script>пример</script>` остаётся текстом, а содержание не задаёт собственные
  стили.
- **Опыт:** изменить один разрешённый цвет и пересобрать просмотр без модели.

### T06 — Напечатать пробный PDF

- **Зависит:** T05.
- **Охватывает:** GUIDE §6, §9.
- **Сделать:** подключить Playwright/Chromium; печатать A4 с локальным шрифтом и сохранением цветов; проверить длинный
  текст; превратить все страницы в изображения и осмотреть их.
- **Готово, если:** кириллица читается, нет обрезаний, наложений, случайных пустых страниц и заголовков без продолжения.
- **Опыт:** удлинить абзац и сравнить перенос страниц.

## Этап B — фиксированный путь с Haiku

### T07 — Проверить одно обращение к модели

- **Зависит:** T02.
- **Охватывает:** GUIDE §7, §8.
- **Сделать:** создать отдельный ключ SimpleClaw; добавить `.env` в исключения и `.env.example`; реализовать сетевой
  вызов и `npm run model:check` с ограничением ответа и времени.
- **Готово, если:** короткий ответ получен, неверный ключ даёт понятную ошибку без утечки ключа, списание отмечено по
  кабинету.
- **Опыт:** показать адрес, модель, запрос и получение ответа.

### T08 — Получить структурированный черновик

- **Зависит:** T04, T07.
- **Охватывает:** GUIDE §1, §5, §8.
- **Сделать:** передать модели только статью и нужные правила; запросить русский текст с оговорками, терминами и
  помеченными учебными примерами; проверить ответ и сохранить `draft.json`; добавить `npm run draft -- "ИМЯ_РАБОТЫ"`.
- **Готово, если:** черновик проходит проверку полей, тезисы и ограничения находятся в источнике, пример помечен, а
  неверный ответ не затирает последний корректный файл.
- **Опыт:** сравнить упрощённую версию абзаца и расход запросов.

### T09 — Сделать утверждение обязательным

- **Зависит:** T08.
- **Охватывает:** GUIDE §1, §5, §8, §9.
- **Сделать:** добавить `npm run approve -- "ИМЯ_РАБОТЫ"`; сохранять контрольную строку в `approval.json`; добавить
  `npm run pdf -- "ИМЯ_РАБОТЫ"` с проверкой совпадения содержания.
- **Готово, если:** без утверждения PDF не создаётся, после утверждения создаётся, а изменение одного предложения снова
  блокирует печать.
- **Опыт:** изменить текст после утверждения и разобрать отказ.

### T10 — Соединить полный фиксированный путь

- **Зависит:** T06, T09.
- **Охватывает:** GUIDE §4, §5, §9.
- **Сделать:** соединить загрузку, черновик, просмотр и остановку перед утверждением; показывать текущий шаг и пути
  файлов; повторно использовать сохранённые результаты.
- **Готово, если:** PDF содержит утверждённый текст, повторная печать не вызывает Haiku, ссылка ведёт к выбранной
  статье.
- **Опыт:** объяснить, какие решения всё ещё заданы кодом, а не моделью.

## Этап C — собственный агентный цикл

### T11 — Проверить запрос одного инструмента

- **Зависит:** T07.
- **Охватывает:** GUIDE §3, §4, §8.
- **Сделать:** описать `get_document_status`; выполнить запрос модели в программе; вернуть результат с тем же id вызова;
  отправить следующий запрос и проверить формат SimpleClaw.
- **Готово, если:** журнал содержит запрос инструмента, результат и следующий ответ; ключ и скрытые настройки
  отсутствуют.
- **Опыт:** передать модели статус «текст не утверждён» и проследить его путь.

### T12 — Проверять и выполнять разрешённые инструменты

- **Зависит:** T10, T11.
- **Охватывает:** GUIDE §4, §5, §8.
- **Сделать:** оформить `fetch_article`, `save_draft`, `validate_draft`, `get_document_status`, `render_pdf`; проверять
  имя, поля, типы и закреплённую рабочую папку; не давать модели инструмент утверждения.
- **Готово, если:** допустимое действие выполняется, неизвестное отклоняется, лишнее поле пути отклоняется, печать без
  утверждения не создаёт PDF.
- **Опыт:** проверить поддельный вызов без платного запроса.

### T13 — Ограничить цикл ответов и действий

- **Зависит:** T12.
- **Охватывает:** GUIDE §4, §8, §9.
- **Сделать:** реализовать цикл «ответ → проверка → функция → результат → ответ»; последовательно обрабатывать несколько
  вызовов; ограничить число запросов, длину, ожидание и повторы; различать итоговые статусы.
- **Готово, если:** подготовленные ответы проходят два действия, раннее «готово» без результата не принимается, лимит
  останавливает цикл.
- **Опыт:** временно установить максимум два обращения.

### T14 — Продолжить после решения человека

- **Зависит:** T09, T13.
- **Охватывает:** GUIDE §4, §5, §8, §9.
- **Сделать:** добавить `npm run agent -- "URL"` и `npm run agent:resume -- "ИМЯ_РАБОТЫ"`; остановить первый запуск на
  утверждении; при продолжении читать актуальные файлы и печатать только утверждённую версию.
- **Готово, если:** до решения PDF отсутствует, после утверждения создаётся, перезапуск не теряет состояние, старое
  утверждение не используется.
- **Опыт:** отклонить первый текст, исправить блок, утвердить заново и проверить PDF.

### T15 — Сделать журнал понятным

- **Зависит:** T14.
- **Охватывает:** GUIDE §5, §7, §8, §9.
- **Сделать:** писать `trace.jsonl` с шагом, моделью, инструментом, временем, результатом и причиной остановки; отделить
  токены от рублей; ограничить повтор ошибки двумя попытками; учитывать бюджет.
- **Готово, если:** запуск восстанавливается по журналу, повторяющаяся ошибка останавливается, ключ и `Authorization` не
  записываются; неизвестный расход обозначен явно.
- **Опыт:** определить шаг остановки только по журналу.

## Этап D — качество и приёмка

### T16 — Не принимать непроверенное содержание

- **Статус:** выполнено и проверено.

- **Зависит:** T14.
- **Охватывает:** GUIDE §1, §8, §9.
- **Сделать:** запускать обязательную проверку структуры после черновика; создать `report.json` и лист ручной сверки;
  возвращать модели конкретные ошибки, после двух неудач останавливать процесс для человека.
- **Готово, если:** отсутствующая ссылка и неподписанный пример блокируют принятие; человек сверил тезисы и оговорки с
  источником.
- **Опыт:** проверить неподтверждённое утверждение с существующей ссылкой и объяснить предел автоматизации.

### T17 — Проверить страницы итогового PDF

- **Статус:** выполнено и проверено.

- **Зависит:** T06, T14.
- **Охватывает:** GUIDE §6, §9.
- **Сделать:** запретить произвольные стили; собрать документ с длинным заголовком, ссылкой, списком и русским текстом;
  осмотреть изображения всех страниц; исправить ошибки шаблона.
- **Готово, если:** все страницы просмотрены, нет обрезаний и наложений, PDF соответствует утверждённому содержанию,
  статус ручного осмотра честный.
- **Опыт:** сравнить HTML-просмотр с напечатанным PDF.

### T18 — Проверить отказы и границы доступа

- **Зависит:** T12, T15.
- **Охватывает:** GUIDE §8, §9.
- **Сделать:** проверить неверный адрес, чужой редирект, пустую статью, неверные поля модели, отказы сети, тайм-аут,
  лимит шагов и текст prompt injection; сохранить прежний корректный черновик.
- **Готово, если:** каждый случай даёт понятный отказ, ключи и файлы вне рабочей папки не читаются инструментами.
- **Опыт:** назвать действие, которое запрещено кодом даже при просьбе модели.

### T19 — Добавить новый инструмент вместе с помощником

- **Статус:** выполнено и объяснено своими словами.

- **Зависит:** T13, T16.
- **Охватывает:** GUIDE §1, §3, §9.
- **Сделать:** добавить `find_unexplained_terms` с явным списком терминов; зарегистрировать описание и параметры;
  вернуть результат модели и записать вызов.
- **Готово, если:** термин без объяснения обнаруживается, объяснённый термин принимается, результат виден в журнале,
  ручная проверка понятности не подменяется инструментом.
- **Опыт:** самостоятельно добавить термин в список и повторить проверку.

### T20 — Пройти приёмку на новой статье

- **Зависит:** T15, T16, T17, T18, T19.
- **Охватывает:** GUIDE §9, §11.
- **Сделать:** выбрать вторую статью OpenAI; пройти весь путь до PDF и осмотра страниц; запустить `npm test` и
  `npm run typecheck`; обновить README и запись об обучении.
- **Готово, если:** таблица приёмки GUIDE пройдена, журнал относится к новой статье, выполненное и непроверенное
  разделены, полный круг и новый инструмент объяснены своими словами.
- **Опыт:** показать проверку, которая обнаруживает «модель сказала готово, но файла нет».

## Этап E — после T20: ручной редактор

### E01 — Открыть существующий документ

- **Зависит:** T20.
- **Охватывает:** GUIDE §10.
- **Сделать:** добавить локальное окно выбора работы и предпросмотра; использовать существующее содержание и шаблон; не
  передавать ключ в браузер.
- **Готово, если:** документ открывается без генерации, предпросмотр совпадает с правилами печати, ключ модели
  отсутствует в данных браузера.

### E02 — Редактировать и сохранять текст

- **Зависит:** E01.
- **Охватывает:** GUIDE §10.
- **Сделать:** добавить выбор блока, редактирование, мгновенный локальный предпросмотр и явное сохранение; сбрасывать
  прежнее утверждение после ручной правки.
- **Готово, если:** изменение видно сразу, сохраняется после открытия, запросов к Haiku во время ввода нет.

### E03 — Выбирать оформление в пределах правил

- **Зависит:** E02.
- **Охватывает:** GUIDE §6, §10.
- **Сделать:** добавить выбор разрешённого вида блока и цветов из `DESIGN-PDF.md`; проверять значения при сохранении; не
  принимать произвольный CSS.
- **Готово, если:** допустимое оформление видно и сохраняется, неподдерживаемое отклоняется, PDF использует выбранное
  правило.

### E04 — Управлять блоками и отменять действия

- **Зависит:** E02.
- **Охватывает:** GUIDE §5, §10.
- **Сделать:** добавить создание, удаление, перемещение блоков и отмену последнего действия; сохранять постоянные id и
  ссылки на источник.
- **Готово, если:** операции работают, отмена восстанавливает состояние, порядок после сохранения совпадает с
  просмотром.

### E05 — Печатать отредактированный документ

- **Зависит:** E03, E04.
- **Охватывает:** GUIDE §5, §8, §10.
- **Сделать:** добавить утверждение текущей версии и сборку PDF поверх существующей проверки; показывать версии
  просмотра и печати.
- **Готово, если:** PDF соответствует последним сохранённым данным, новая правка требует нового утверждения, ошибка
  печати не теряет изменения.

### E06 — Предлагать правки моделью безопасно

- **Зависит:** E05.
- **Охватывает:** GUIDE §8, §10.
- **Сделать:** добавить предложение правки выбранного блока; показывать ответ рядом с текущим текстом; применять только
  после выбора человека и проверки версии блока.
- **Готово, если:** отклонение сохраняет ручной текст, принятие меняет только выбранный блок, запоздалый ответ не
  затирает новую правку.

## Стартовый тикет

Начать с **T01**. После его выполнения должны появиться `LEARNING.md`, схема одного
круга работы агента и объяснение пяти понятий. Следующий тикет — T02; платные
обращения к модели начинаются только с T07.
